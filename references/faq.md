## 1. `scope check 127.0.0.1` 为什么也被拒绝？

Scope Guard 默认 deny：即使本地靶场也必须先 `scope add --type training/local-lab --target ...` 登记。口头说“这是我自己环境”不会被当作授权，授权以 scope.json 为准。

## 2. 公网真实站点为什么不能直接测？

未授权公网目标默认拒绝（exit 1），SRC/bug bounty 目标必须先在平台页面确认范围，再用 `scope add --type bug-bounty --target ...` 登记后才测；每轮只测授权范围内的资产。

## 3. SRC 测试怎么开始？

先看平台授权范围（域名/资产/时间/规则），按范围登记 scope，再做侦察→发现→验证→报告。碰到真实用户数据、越权到平台未授权资产、生产数据时立即停手，只保留最小证据。

## 4. 四阶段和 playbook 怎么配合？

先读 `playbooks/00-methodology.md` 建立整体流程，再按目标功能选对应漏洞 playbook（SQLi/XSS/SSRF 等）。每阶段结束重新 `scope check`，动作变化都要确认仍在授权范围。

## 5. 为什么没有可复制的 payload？

本技能定位是“有纪律的授权测试方法论 + 对抗知识映射”，不做可执行 payload、免杀、钓鱼、社工输出。实际验证应在靶场/授权目标内由人工按方法执行，AI 负责思路、流程、记录与报告。

## 6. 报告怎么生成？

先把验证结论整理成 findings.json（字段见 references/report-template.md），再运行 `report generate findings.json --out report.md`；报告会统计严重级、保留证据锚点并自动脱敏敏感凭据。

## 7. 操作留痕可以关掉吗？

不可以静默关闭。audit log 默认记录 init/add/check/report 等动作；想审查记录用 `audit log --result deny` 或 `--export` 导出，这是 Scope Guard 的可追溯设计。

## 8. 提示 scope 未初始化/格式错误，退出码是什么？

未初始化、找不到 scope.json、非法授权条目等为 exit 3/4；未授权目标拒绝为 exit 1；云元数据等绝对禁止为 exit 2。报错文案会直接告诉你下一步，比如先 `scope init` 或检查日期/类型。

## 9. 测试到一半发现目标过期/范围变化怎么办？

先停手。用 `scope check` 重新判定，过期条目会按 deny 处理；若新范围未登记，不要继续测，先补充授权条目并确认平台规则。

## 10. 安装不上/没有触发怎么办？

用 `npx -y @yottameta/yotta-security-testing --agent <名称>` 或 `--dir <技能目录>` 安装。它是主动测试方法论技能，收到“帮我看这个站/测这个靶场/挖 SRC”类请求时触发；真实目标先登记授权，靶场先本地登记。

## 11. 元测和元析/元安全怎么分工？

元析做网络侦察/指纹识别（不主动攻击）；元测做授权范围内的四阶段 Web 测试方法论；元安全是给 AI 技能/环境自身做加固体检。元测能串起元安/元钥/元鉴作为报告证据链，但各自边界不同。

## 12. 测试结果可靠吗？

本技能输出方法论、测试点清单和报告草稿，不替代专业渗透测试；每个结论都应由授权测试者人工复核，重要风险在报告中标注“待人工核验”后再提交。
