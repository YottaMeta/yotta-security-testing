# Playbook 05：反序列化测试

> 覆盖：OWASP Top 10 2021 A08 Software & Data Integrity｜CWE-502｜源域 web-deserialization
> 纪律：只做方法论与弱点原理教学；验证输入一律「类」表述，不给可复制注入串；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确目标与授权范围；记录目标 / 授权类型 / 授权来源 / 边界。
- 未授权目标 → 拒绝，先 `scope init` + `scope add`。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **输入点枚举**：携带序列化数据的 Cookie / 会话标识、请求体中的序列化格式字段、文件上传（序列化对象文件）、消息队列 / 缓存类输入。
- **测试点筛选**：服务端会对不可信输入做反序列化的位置（会话还原、对象导入）。
- **判定标准（候选信号）**：
  - 篡改序列化数据后，服务端行为出现差异（解析报错 / 状态变化 / 功能异常）；
  - 序列化格式特征可识别（语言特定的类结构 / 魔术方法类关键字）。

## 3. 验证方法（最小验证步骤）

- 先识别序列化格式与语言（观察数据结构的「类」特征，如类型标记 / 字段长度头）。
- 用**无害的结构修改**（改字段值 / 截断）观察反序列化行为差异——不构造可执行对象链。
- 判定：仅当「反序列化处理不可信输入」被证实且影响在授权范围内时记为候选发现；记录请求 / 响应证据。
- 边界：不构造 gadget 链、不执行对象注入、不尝试远程执行；验证到「可复现的解析差异」即止。

## 4. 防御视角（修复 / 防护建议）

- 不用原生反序列化处理不可信输入；对必须反序列化的数据加签名 / 加密校验。
- 反序列化前做类型白名单过滤；升级依赖修复已知反序列化漏洞；监控异常解析告警。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **OWASP Juice Shop**：Cookie / 会话类关卡——观察序列化数据格式与篡改后的行为差异（按关卡指引）。
- **DVWA**：无内置反序列化关卡，可自建本地小应用演练（本地靶机需先授权）。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
