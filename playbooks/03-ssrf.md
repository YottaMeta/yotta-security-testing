# Playbook 03：SSRF 服务端请求伪造测试

> 覆盖：OWASP Top 10 2021 A10 SSRF｜CWE-918｜源域 web-ssrf
> 纪律：只做方法论与弱点原理教学；验证输入一律「类」表述，不给可复制注入串；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确目标与授权范围；记录目标 / 授权类型 / 授权来源 / 边界。
- 未授权目标 → 拒绝；注意：云元数据类目标（如 169.254.169.254）为**绝对禁止**，白名单也无法覆盖。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **输入点枚举**：图片 / 文件 / 预览类 URL 参数、webhook / 回调 / 导入功能、代理转发功能、PDF 生成含 URL 的输入。
- **测试点筛选**：服务端会「代为发起请求」的输入（URL 下载 / 抓取 / 导入）。
- **判定标准（候选信号）**：
  - 提交内部地址类目标后，响应内容 / 时间 / 报错出现差异（说明服务端确实发起了请求）；
  - 用自己可控的接收端观察是否收到来自服务端的请求。

## 3. 验证方法（最小验证步骤）

- 先用**自己可控的接收端**（如授权范围内的回显服务）确认服务端会请求用户提供的地址——这是「类」验证，不触碰内部目标。
- 再按授权范围判断服务端对内网地址的访问行为（仅在授权允许时，用明确记录在案的地址）。
- 判定：仅当「服务端发起请求」被证实且影响在授权范围内时记为候选发现；记录请求 / 响应证据。
- 边界：**绝不实际请求云元数据地址**（绝对禁止清单）；不扫描内网段；验证到「可复现的外发请求」即止。

## 4. 防御视角（修复 / 防护建议）

- URL 白名单（协议 / 域名 / 端口）；禁用 DNS 重绑定类绕过（解析后二次校验）。
- 禁止跟随重定向；出网访问按最小化策略限制；回环 / 内网 / 元数据地址在服务端入口拦截。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **OWASP Juice Shop**：图片导入 / URL 类功能关卡——用授权回显端验证服务端请求行为。
- **DVWA**：无内置 SSRF 关卡，可自建本地小应用演练 URL 抓取功能（本地靶机需先授权）。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
