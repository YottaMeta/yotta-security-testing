# Playbook 02：XSS 跨站脚本测试

> 覆盖：OWASP Top 10 2021 A03 Injection｜CWE-79｜源域 web-xss
> 纪律：只做方法论与弱点原理教学；验证输入一律「类」表述，不给可复制注入串；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确目标与授权范围；记录目标 / 授权类型 / 授权来源 / 边界。
- 未授权目标 → 拒绝，先 `scope init` + `scope add`。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **XSS 三类**：反射型（输入经响应原样回显）、存储型（输入持久化后在其他页面渲染）、DOM 型（前端脚本读取输入并写入页面）。
- **输入点枚举**：搜索框、URL 参数回显、评论 / 留言 / 昵称等可提交内容、富文本编辑、错误提示回显。
- **判定标准（候选信号）**：
  - 提交的标记类文本（含尖括号与引号类字符）被原样渲染为页面内容；
  - 浏览器解析后出现可执行类行为（脚本执行 / 跳转 / 弹窗类现象）；
  - DOM 型：前端源码显示输入被直接拼入页面写入逻辑。

## 3. 验证方法（最小验证步骤）

- 先确认输出位置：输入在响应的 HTML / 属性 / 脚本上下文中的位置。
- 用**无害标记类**输入（如带尖括号的普通文本）观察是否被转义或原样渲染——不携带可执行脚本。
- 判定：仅当「输入被当作代码上下文解析」且现象可复现时记为候选发现；记录请求 / 响应 / 渲染证据。
- 边界：不做会话窃取类演示、不写可执行脚本串；验证到「可被当作代码解析」即止。

## 4. 防御视角（修复 / 防护建议）

- 输出编码（按上下文：HTML / 属性 / JS / URL）；输入白名单校验；CSP 限制脚本来源。
- 敏感 Cookie 加 HttpOnly + Secure；DOM 型修复前端写入逻辑（不用不可信输入拼 HTML）。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **DVWA**：Reflected XSS / Stored XSS 页面——分别对搜索框与留言功能做输入点枚举与渲染观察。
- **OWASP Juice Shop**：XSS 类关卡（评论 / 搜索等）——确认输出上下文与转义情况。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
