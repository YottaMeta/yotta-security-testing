# Playbook 01：SQL 注入测试（SQLi）

> 覆盖：OWASP Top 10 2021 A03 Injection｜CWE-89｜源域 web-sqli
> 纪律：只做方法论与弱点原理教学；验证输入一律「类」表述，不给可复制注入串；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确目标 URL / 域名 / IP，确认在 scope.json 授权范围内；未授权 → 拒绝，先 `scope init` + `scope add`。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。
- 记录目标 / 授权类型 / 授权来源 / 本次测试范围边界。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **输入点枚举**：带查询参数的 URL、登录表单、搜索框、排序 / 分页参数、JSON / XML 请求体、Cookie、Header。
- **测试点筛选**：与后端数据库交互的输入（查询 / 登录 / 搜索 / 标识类参数）。
- **判定标准（候选信号）**：
  - 输入结构闭合类字符（单引号 / 双引号类）后，响应出现错误信息或行为变化；
  - 布尔条件类输入（真 / 假条件）引起页面内容差异；
  - 时间延迟类输入引起响应时间可观测差异。

## 3. 验证方法（最小验证步骤）

- 用浏览器开发者工具 / 抓包工具观察请求与响应，记录参数位置与编码方式。
- 逐参数插入「结构闭合类」字符，观察响应差异（错误信息 / 状态码 / 页面内容）。
- 用「布尔条件类」与「时间延迟类」输入做对照，确认行为差异可重复。
- 判定：仅当行为差异可复现且与数据库语义吻合时记为候选发现；记录请求 / 响应证据。
- 边界：不执行数据外传、不尝试提权、不批量导出数据；验证到「可复现差异」即止。

## 4. 防御视角（修复 / 防护建议）

- 参数化查询 / 预编译语句（首选）；输入白名单校验；数据库账号最小权限。
- 错误信息脱敏（不向客户端回显数据库错误）；WAF 只作纵深防御，不替代参数化查询。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **DVWA**：SQL Injection 页面——对标识类参数做输入点枚举与验证，观察错误信息与内容差异；按安全级别从低到高复现思路变化。
- **OWASP Juice Shop**：登录 / 搜索相关功能中的注入类关卡——先枚举输入点，再按上述验证方法确认。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 references/report-template.md 的 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
