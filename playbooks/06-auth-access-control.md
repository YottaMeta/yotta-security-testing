# Playbook 06：鉴权与访问控制测试

> 覆盖：OWASP Top 10 2021 A01 / A07 Broken Access Control｜CWE-287 / CWE-352 / CWE-862｜源域 web-auth-bypass + web-access-control
> 纪律：只做方法论与弱点原理教学；验证输入一律「类」表述，不给可复制注入串；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确目标与授权范围；记录目标 / 授权类型 / 授权来源 / 边界（含可用账号的角色）。
- 未授权目标 → 拒绝，先 `scope init` + `scope add`。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **输入点枚举**：登录 / 注册 / 找回密码、会话管理（Cookie / token）、角色与权限接口、资源标识类参数（对象 ID / 文件 ID）、管理后台入口。
- **测试点筛选**：
  - 越权（水平：同角色访问他人资源；垂直：低权限访问高权限功能）；
  - 认证缺陷（弱口令策略、验证码绕过类、会话固定 / 会话失效缺失）；
  - 接口层授权缺失（前端隐藏 ≠ 后端拦截）。
- **判定标准（候选信号）**：
  - 未登录 / 低权限账号可直接访问受限资源或接口；
  - 修改资源标识类参数可访问他人数据（标识符遍历类行为）；
  - 会话在登出 / 改密后仍可继续使用。

## 3. 验证方法（最小验证步骤）

- 准备**授权范围内的多个角色账号**（如普通用户 / 管理员），做对照访问。
- 用「低权限账号访问高权限接口」与「改资源标识访问他人资源」两类最小验证，观察是否被服务端拒绝。
- 判定：仅当「服务端未做授权校验」被证实且影响在授权范围内时记为候选发现；记录请求 / 响应证据。
- 边界：不批量遍历他人数据、不尝试爆破口令、不实际窃取会话；验证到「可复现的越权」即止。

## 4. 防御视角（修复 / 防护建议）

- 服务端每个接口强制授权校验（不依赖前端隐藏）；资源访问按属主校验（对象级授权）。
- 最小权限原则；会话安全（HttpOnly / Secure / 过期 / 登出失效）；登录限速与告警。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **OWASP Juice Shop**：越权 / 标识符类关卡——用两个角色账号对照访问受限资源。
- **DVWA**：无内置越权关卡，可结合本地多账号环境演练（本地靶机需先授权）。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
