# Playbook 04：XXE 外部实体测试

> 覆盖：OWASP Top 10 2021 A05 Security Misconfiguration｜CWE-611｜源域 web-xxe
> 纪律：只做方法论与弱点原理教学；验证输入一律「类」表述，不给可复制注入串；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确目标与授权范围；记录目标 / 授权类型 / 授权来源 / 边界。
- 未授权目标 → 拒绝，先 `scope init` + `scope add`。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **输入点枚举**：接收 XML 的请求体（SOAP 接口、XML 导入 / 上传、配置类提交）、文档解析功能。
- **测试点筛选**：服务端会解析 XML 的输入；确认请求的 Content-Type 与格式。
- **判定标准（候选信号）**：
  - 声明外部实体类 XML 后，响应中出现实体内容回显或解析行为变化；
  - 外部实体指向可读资源时，响应 / 报错包含该资源内容类特征；
  - 解析器对畸形 XML 的报错信息暴露内部处理细节。

## 3. 验证方法（最小验证步骤）

- 先确认解析器行为：提交带实体声明类结构的 XML，观察是否解析 / 报错差异。
- 用**自建可控回显资源**（授权范围内）验证外部实体是否被解析——「类」表述，不指向真实内部文件。
- 判定：仅当「外部实体被解析」被证实且影响在授权范围内时记为候选发现；记录请求 / 响应证据。
- 边界：不读取真实敏感文件内容（如口令 / 密钥类文件）、不发起内部探测；验证到「可复现的实体解析」即止。

## 4. 防御视角（修复 / 防护建议）

- 解析器禁用外部实体与 DTD 处理（XXE 防护开关）；优先使用 JSON 等非 XML 格式。
- 若必须支持 XML：关闭外部实体 / 外部 DTD，限制实体数量与大小，错误信息不向客户端回显。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **OWASP Juice Shop**：XXE 类关卡（XML 提交功能）——按上述思路验证实体解析行为。
- **DVWA**：无内置 XXE 关卡，可自建本地 XML 解析小应用演练（本地靶机需先授权）。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
