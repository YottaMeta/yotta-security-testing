# Playbook 12：不安全配置测试（Security Misconfiguration）

> 覆盖：OWASP Top 10 2021 A05 Security Misconfiguration｜自研扩展（老张 2026-08-29 补充）
> 纪律：只做方法论与弱点原理教学；验证「类」表述，不做弱口令爆破、不触碰未授权凭据；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确目标与授权范围；记录目标 / 授权类型 / 授权来源 / 边界。
- 未授权目标 → 拒绝，先 `scope init` + `scope add`。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **输入点枚举**：安全响应头、CORS 策略、错误信息、默认配置（目录列举 / 多余服务 / 调试开关）、TLS 配置、管理接口。
- **测试点筛选**：
  - 安全头缺失（CSP / HSTS / X-Frame-Options 类）；
  - CORS 是否反射任意来源；
  - 报错是否泄露内部信息；目录列举 / 调试接口是否开放；
  - 是否存在默认 / 弱配置（仅判断配置是否存在类问题，不尝试爆破）。
- **判定标准（候选信号）**：
  - 明显不安全配置存在且可被外部观察 / 利用；
  - 配置问题导致信息泄露或降低攻击门槛。

## 3. 验证方法（最小验证步骤）

- 观察响应头与错误行为，记录缺失项与异常项（只读验证）。
- 用「来源反射类」请求验证 CORS 行为；访问目录列举 / 调试类接口确认是否开放。
- 判定：仅当「不安全配置被证实」且影响在授权范围内时记为候选发现；记录请求 / 响应证据。
- 边界：不尝试弱口令 / 默认凭据爆破、不利用配置执行操作；验证到「可复现的配置缺陷」即止。

## 4. 防御视角（修复 / 防护建议）

- 安全响应头（CSP / HSTS / X-Frame-Options / nosniff 类）；CORS 白名单不反射任意来源。
- 错误信息脱敏；关闭目录列举 / 调试 / 多余服务；TLS 强制与证书校验；资产与配置基线管理。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **OWASP Juice Shop**：安全配置类关卡——观察响应头 / CORS / 错误行为（按关卡指引）。
- **DVWA**：无内置配置关卡，可结合本地环境演练（本地靶机需先授权）。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
