# Playbook 10：业务逻辑漏洞测试（Business Logic）

> 覆盖：OWASP Top 10 2021 A01 Broken Access Control / A04 Insecure Design｜自研扩展（老张 2026-08-29 补充，SRC 高发）
> 纪律：只做方法论与弱点原理教学；验证在授权范围内用测试数据演练，「类」表述，不实际牟利；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确目标与授权范围；记录目标 / 授权类型 / 授权来源 / 边界（含可用测试账号与数据）。
- 未授权目标 → 拒绝，先 `scope init` + `scope add`。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **输入点枚举**：订单 / 支付 / 优惠券 / 积分 / 抽奖 / 验证码 / 邀请码 / 订阅等业务流程。
- **测试点筛选**：
  - 参数篡改：价格 / 数量 / 金额 / 折扣 / 状态类字段是否被服务端信任；
  - 步骤跳跃：跳过前置步骤（如支付前先确认、先验证后提交）直接访问后续状态；
  - 次数与并发：领取 / 兑换 / 抽奖次数限制是否可绕过（并发 / 重放）；
  - 状态机：订单 / 用户状态流转是否存在非法迁移。
- **判定标准（候选信号）**：
  - 篡改业务参数后产生异常利益或越权操作；
  - 流程步骤可被跳过 / 重放 / 并发绕过限制。

## 3. 验证方法（最小验证步骤）

- 先梳理业务流程与状态流转，建立「步骤 × 参数 × 权限」对照。
- 用**测试账号与测试数据**（授权范围内）做参数篡改 / 步骤跳跃 / 并发最小验证，观察服务端是否校验。
- 判定：仅当「服务端缺少业务校验」被证实且影响在授权范围内时记为候选发现；记录请求 / 响应证据。
- 边界：不实际薅羊毛 / 不产生真实资金损失 / 不污染真实数据；验证到「可复现的业务校验缺陷」即止。

## 4. 防御视角（修复 / 防护建议）

- 业务参数服务端强校验（金额 / 数量 / 状态不信任客户端）；幂等与事务保证。
- 流程状态机 + 防重放（nonce / 一次性 token）；并发控制与风控告警。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **OWASP Juice Shop**：支付 / 优惠券类关卡——用测试账号演练参数篡改与流程校验（按关卡指引）。
- **DVWA**：无内置业务逻辑关卡，可自建本地小应用演练（本地靶机需先授权）。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
