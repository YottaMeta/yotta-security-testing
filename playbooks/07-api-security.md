# Playbook 07：API 安全测试

> 覆盖：OWASP API Security Top 10 映射｜源域 api-security
> 纪律：只做方法论与弱点原理教学；验证输入一律「类」表述，不给可复制注入串；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确 API 目标（域名 / 版本 / 认证方式）与授权范围；记录目标 / 授权类型 / 授权来源 / 边界。
- 未授权目标 → 拒绝，先 `scope init` + `scope add`。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **输入点枚举**：API 文档与端点清单、认证与授权机制（token / 密钥 / 会话）、请求体字段、批量操作 / 分页参数、错误响应、速率限制。
- **测试点筛选（对照 OWASP API Top 10）**：
  - 对象级授权缺失（BOLA：改资源标识访问他人数据）；
  - 对象属性级授权缺失（BDBA：修改他人对象的字段）；
  - 过度数据暴露（响应返回多余敏感字段）；
  - 批量分配（请求体多余字段被写入对象）；
  - 认证失效 / 会话管理缺陷 / 无速率限制 / 注入 / 不安全资产（影子 API）。
- **判定标准（候选信号）**：
  - 低权限 token 可访问高权限端点或他人资源；
  - 响应包含未声明使用的敏感字段；
  - 请求体额外字段被服务端接受并持久化；
  - 错误响应泄露内部实现细节。

## 3. 验证方法（最小验证步骤）

- 先从 API 文档梳理端点与权限模型，建立「端点 × 角色 × 方法」对照表。
- 用「低权限访问高权限端点」「修改资源标识」「追加多余字段」三类最小验证观察服务端行为。
- 判定：仅当「服务端未做授权 / 校验」被证实且影响在授权范围内时记为候选发现；记录请求 / 响应证据。
- 边界：不批量拉取他人数据、不爆破 token、不尝试提权；验证到「可复现的授权 / 校验缺陷」即止。

## 4. 防御视角（修复 / 防护建议）

- 服务端对象级授权 + 最小响应字段（按需返回）；输入白名单 + 批量分配防护。
- 认证 token 安全存储与过期；全局限速与异常告警；API 资产管理（下线影子端点）；错误信息脱敏。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **OWASP Juice Shop**：REST API 类关卡——按「端点 × 角色」对照表演练越权与过度数据暴露。
- **DVWA**：无内置 API 关卡，可结合本地 API 演练环境（本地靶机需先授权）。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
