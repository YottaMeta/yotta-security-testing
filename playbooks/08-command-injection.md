# Playbook 08：命令注入测试（Command Injection）

> 覆盖：OWASP Top 10 2021 A03 Injection｜CWE-78｜自研扩展（老张 2026-08-29 补充，SRC 高发）
> 纪律：只做方法论与弱点原理教学；验证输入一律「类」表述，不给可复制注入串；
> 动手前先 `scope check` 确认目标在授权范围内。

## 1. 目标识别与确认（先过 Scope Guard）

- 明确目标与授权范围；记录目标 / 授权类型 / 授权来源 / 边界。
- 未授权目标 → 拒绝，先 `scope init` + `scope add`。
- SRC / 真实目标：先读取平台授权范围与测试规则（scope 页面 / 授权邮件），确认目标 in-scope 后再登记授权。

## 2. 检测思路（输入点枚举 → 测试点 → 判定标准）

- **输入点枚举**：会把输入交给操作系统命令执行的功能——连通性检测类（ping / traceroute）、域名查询类（whois / nslookup）、文件 / 压缩包处理、下载 URL 处理、定时任务表达式。
- **测试点筛选**：确认后端存在命令拼接的输入（功能语义即「执行命令」的输入）。
- **判定标准（候选信号）**：
  - 输入中追加命令控制类字符后，响应出现命令执行结果类内容；
  - 输入不合法时报错暴露底层命令片段。

## 3. 验证方法（最小验证步骤）

- 先观察正常输入与响应基线。
- 用**无害可观察命令类**输入验证拼接（如回显类内容）——「类」表述，不执行破坏性 / 外连 / 反弹类命令。
- 判定：仅当「用户输入被拼入命令执行」被证实且影响在授权范围内时记为候选发现；记录请求 / 响应证据。
- 边界：不执行数据外传、不尝试提权、不反弹 shell；验证到「可复现的命令拼接」即止。

## 4. 防御视角（修复 / 防护建议）

- 不拼接系统命令：用参数化执行 / 白名单映射（功能选项目录，不直接拼输入）。
- 输入白名单校验（域名 / IP 格式）；命令执行进程最小权限 + 沙箱；错误信息不向客户端回显。

## 5. 实战演练（靶场 / 授权目标 / SRC）

**靶场练手**：
- **DVWA**：Command Injection 页面——对连通性检测类输入做输入点枚举与验证，观察输出差异。
- **OWASP Juice Shop**：无内置命令注入关卡，可结合本地小应用演练（本地靶机需先授权）。
- 完成一轮后把验证记录整理进发现清单。

**授权目标 / SRC 场景**：
- 先在平台授权范围（scope 页面 / 授权邮件）确认目标 in-scope，用 `--type bug-bounty` 登记后再测；规则与 SLA 以平台为准。
- 遵守平台测试规则：禁测项（如未授权接口 / 生产数据）、限速、不触碰未授权数据；发现真实用户数据即停手并最小化证据。
- 对真实目标同样走本 playbook 的「输入点枚举 → 验证 → 判定」流程，验证到「可复现差异」即止。
- 漏洞按平台模板提交（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏。


## 6. 留痕与报告

- 每轮操作自动写入 audit.log（目标 / 动作 / 时间 / 结果）。
- 按 findings schema 记录：标题 / 严重级 / 类别 / CWE / 端点 / 描述 / 证据 / 修复建议。
- `report generate findings.json --out report.md` 生成报告，确认敏感凭据已脱敏。
- SRC / 平台提交：按平台模板整理报告（标题 / 影响 / 复现步骤 / 危害等级 / 修复建议），证据先脱敏；不留存真实用户数据。
